1Purpose and product summary

Version 2.0 update (Part 3). Requirements FR-21 to FR-23 (Google SSO, real-time push, due-date reminders) are new. FR-05 and FR-18 are now fully implemented, and the defects behind FR-01 and FR-02 are fixed. Each row states its current status.

Nexus is an Android app for personal project planning and habit tracking, backed by a small Node.js/Express REST API in backend/. The README describes it as "a calm, focused Android workspace for project planning and habit tracking". This document records what the product does at the evidence baseline, what it deliberately does not do, and how each requirement can be accepted. Requirement IDs (FR-nn, NFR-nn, CON-nn) are referenced by every other deliverable.

How to read status. Implemented means the behaviour exists in source at the baseline commit; it does not by itself mean the behaviour was exercised end-to-end on a device for this package. Verified test results are listed in NX-09-TDH. Gaps are tracked as findings in NX-08-AUD and as tasks in NX-06-PLAN.

3Scope

3.1In scope (implemented)

  • Account lifecycle: register, sign in (email/password or Google SSO), persisted session, sign out, profile, preferences, password change, account deletion.
  • Notifications: scheduled due-date reminders and real-time push of changes made on another device.
  • Projects with tasks (due date, priority, status, labels, checklist), search and filters.
  • Habits with daily completion, streaks, points, levels, badges and CSV export.
  • Offline-first local saves with an ordered upload queue, sync status banner and conflict review.
  • English, isiZulu and Setswana on every screen; light/dark/system theme; animated splash that respects reduced motion.

3.2Out of scope or planned (not implemented)

From PROJECT_IMPROVEMENTS.md ("Still planned") and docs/POE_PART_2_ADDENDUM.md: board/calendar/timeline views, recurring tasks, attachments/templates/archive, collaboration/roles/comments, account recovery, general import/export, widgets, tablet layouts, and SQLite on the server. None of these exist in code Implemented. Google SSO, push notifications, reminders and full localisation were planned for the final PoE and are now implemented (FR-21 to FR-23, FR-18).

4Functional requirements

Acceptance criteria are written so a tester can run them against the debug build and a local API (setup in NX-11-DEP).

Functional requirements and acceptance criteria

FR-01Register an account with display name, email and password.Blank fields, a malformed email or a password under 6 characters are rejected on the device before sending. API returns 201 and a JWT; a duplicate email returns 409 EMAIL_ALREADY_REGISTERED, which the app explains ("An account with this email already exists"). Emails are case-insensitive.AuthViewModel.kt, registerSchema Implemented; fixed in v2.0 (AUD-18, AuthErrorMessagesTest)

Wrong credentials (401 INVALID_CREDENTIALS) show "Email or password is incorrect." Sign-in requires the API; there is no offline sign-in.TokenManager.kt, tokenFor() Implemented; verified on device 2026-11-05 (AUD-18 fixed)
FR-03Sign out.A confirmation dialog appears; confirming clears the token and returns to Login. Unsent changes stay on the device and upload only when the same account signs in again.LogoutConfirmationDialog.kt, docs/ONLINE_OFFLINE.md Implemented
FR-04View and edit the profile display name.Profile shows display name and email; Settings saves a new display name via PATCH /users/me. A cached profile is shown offline.ProfileScreen.kt, UserRepository.kt Implemented
FR-05Account preferences: language and notification preference.Changing language (en/zu/tn) or the reminders switch sends a partial PATCH /users/me. FR-08Delete account and all data.A confirmation dialog ("This permanently deletes your account and synced data.") precedes deletion. The API removes the user, projects, tasks and habits; the app purges that account's local rows and queue, then signs out.SettingsScreen.kt, DELETE /users/me, NexusApp.kt purge callback Implemented
FR-09Dashboard ("Today") overview.Shows counts for projects, tasks and activity (completed tasks), plus "Your schedule" cards: Overdue, Due today and the next 3 Upcoming incomplete tasks. FR-10Create, view, edit, delete and search projects.A project needs a non-empty name; description is optional. Search filters the list by name. Deleting a project also deletes its tasks locally and on the server.ProjectListScreen.kt, ProjectDetailScreen.kt, ProjectRepository.kt Implemented
FR-11Create, edit, complete and delete tasks within a project.A task has title (required), description, due date (yyyy-MM-dd), priority (None/Low/Medium/High), status (To do/In progress/Done), labels and checklist steps. FR-12Find tasks quickly.Task list offers text search over title and labels, status chips (All, Open, In progress, Done) and a High priority chip; shows progress "x of y tasks complete". FR-13Create, edit, delete and complete habits.A habit has a name and frequency (Daily, Weekly, Custom). "Complete today" toggles today's date in completedDates; the button reads "Completed today" when done.HabitsScreen.kt, HabitCard.kt, HabitsViewModel.kt Implemented
FR-14Habit progress and rewards.Habits screen shows level, points, current and best streak, completion rate, badges (3-day streak, 7-day streak, Reliable habit builder) and reward suggestions, all computed on the device.HabitScoring.kt, HabitScoringTest.kt Implemented; AUD-17 fixed in v2.0
FR-15Export habit history as CSV.Settings, then "Export habits CSV" builds habit,frequency,completed_date rows; "Share CSV" opens the Android share sheet with text/csv.SettingsViewModel.exportCsv(), CsvRowTest Implemented; AUD-11 fixed (RFC 4180 quoting)
FR-16Work offline and sync later.Project, task and habit creates, edits and deletes are saved to Room together with an upload record in one transaction, and they survive an app restart. Uploads run on refresh, when the network returns, when you tap Sync, and every 30 s while the process is alive. The banner shows the pending count and state.SyncManager.kt, NexusApp.kt, OfflinePersistenceTest.kt Implemented
FR-17Handle sync conflicts without losing data silently.Retried operations are never duplicated (server keeps operation receipts). An edit to an item deleted elsewhere returns 409 and stops the queue; Review offers "Keep changes" or "Discard item edits". Existing-item edits are last-upload-wins./api/sync, sync.test.js Implemented
FR-18Use the app in English, isiZulu or Setswana.Selecting a language (login screen or Settings) switches every screen, dialog, error, sync message and notification. Each locale has 210 strings and 4 plurals, generated from one catalogue. Translations need first-language review.docs/i18n/catalog.py, values-zu, values-tn, LocalizedMessages.kt Implemented; verified on device (screenshots 14–18)
FR-19Animated splash and motion that respect accessibility settings.With system animations disabled, the splash and screen transitions render without animation.SplashIntroScreen.kt, Motion.kt, SplashIntroScreenTest.kt Implemented
FR-20Show server notices.The Dashboard shows a banner for maintenance mode or the first announcement from GET /app/config. The API always returns maintenance off and no announcements.RemoteConfigViewModel.kt, /api/app/config Implemented
FR-21Sign in with Google (single sign-on)."Continue with Google" appears on Login and Register when the build has a Web client ID. Credential Manager returns a Google ID token; POST /api/auth/google verifies signature, audience, expiry and email verification with Google, creates the account on first use (201) or links an existing email (200), and returns a Nexus JWT. Invalid tokens give 401; an unconfigured server gives 503, which the app explains. A Google-only account cannot use password sign-in (401) or change password (409).GoogleSignIn.kt, server.js, part3.test.js (3 tests, stubbed verifier), AuthErrorMessagesTest Implemented. End to end with real Google: Unknown until the OAuth clients are created
FR-22Real-time push notifications.After sign-in the app registers its FCM token (POST /users/me/devices, at most 10 per user; a token belongs to one account). When a synced change is applied, the API pushes "Project "X" added on another device" to the user's other devices, excluding the sender. The receiving app shows the notification and refreshes its offline cache. Dead tokens are pruned. "Send test notification" in Settings triggers a server push and shows a local one.Push.kt, push.js, part3.test.js (5 tests) Implemented; local display verified on device; FCM delivery Unknown until a Firebase project is configured
FR-23Due-date reminders.With reminders on, a WorkManager job runs about every 12 hours (and immediately after sign-in or switching reminders on). It reads the offline cache and posts "Tasks need your attention: n overdue and m due today" with up to three task titles. It runs while the app is closed and without network. Android 13+ asks for the notification permission.Reminders.kt, ReminderPlanner + ReminderPlannerTest Implemented; verified on device ("1 overdue and 2 due today")

7Success measures

The repository defines no product metrics or analytics. PROJECT_IMPROVEMENTS.md asks that each feature define "one measurable success outcome", but none is recorded Unknown. Recommendation Before the final PoE, agree on two or three measures that can be checked during testing, for example "a task created offline appears on the server within one sync cycle of reconnecting" (FR-16).
