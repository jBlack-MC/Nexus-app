1Scope and method

This audit covers the repository at the evidence baseline: Android source, backend source, build and CI configuration, tests, and existing documentation. The methods were code reading, running both test suites, retrieving GitHub Actions run history, and one targeted reproduction (AUD-01) in a scratch directory.

Not a security audit. No penetration test, threat model, dependency vulnerability scan (npm audit/OWASP) or formal security review was performed. Security-relevant observations below come from reading code and must not be read as a security assessment.

1.1Ratings

  • High: likely data loss, broken core function, or blocked release. Medium: real user or operational impact under plausible conditions. Low: limited impact or quality debt. Info: observation.
  • Confidence: Verified (reproduced or shown in logs/tests), High (unambiguous in code/config), Medium (depends on environment or library behaviour not exercised here).

AUD-01Unreadable data file is silently replaced with an empty store. loadDatabase() catches a JSON parse error, logs it, and continues with empty maps; the next write overwrites the file. AUD-03Open Dependabot PR #27 (Zod 4) breaks all request validation. validate() reads result.error.errors, which is undefined on Zod 4. CI run 2026-10-31 shows TypeError … reading 'map' at server.js:133, so invalid input would return 500 instead of 400. z.record(z.unknown()) in syncSchema also uses the single-argument form that Zod 4 changed (not verified).High (if merged) / VerifiedBackend dependenciesDo not merge as-is; migrate to error.issues and z.record(z.string(), z.unknown()). AUD-02Root docker-compose.yml conflicts with the Docker image. It sets DATABASE_PATH=/usr/src/app/nexus-data.json and bind-mounts a single host file there. The image runs as node with WORKDIR /app, so the server cannot create nexus-data.json.tmp in the root-owned /usr/src/app, and renaming over a bind-mounted file is not possible. If the host file does not exist, Docker creates a directory in its place. backend/compose.yaml (named volume at /data) is consistent.Medium / Medium (not executed; Docker daemon unavailable)Deployment configDelete the root file or align it with backend/compose.yaml.
