6Gaps and how to close them

  • Open question Each member confirms which GitHub account is theirs (if any), and the README is updated with that mapping.
  • Recommendation Record non-code work in the repository: test-session notes with dates and results under docs/, issues assigned to the person doing the work, and PR reviews from the other member, which also adds a second-person review gate.
  • Recommendation If both members commit from a shared machine, set per-person git config user.name/user.email, or use Co-authored-by: trailers.

Until these gaps are closed, individual contribution claims in the PoE should rest on the members' own statements, not on this report.
