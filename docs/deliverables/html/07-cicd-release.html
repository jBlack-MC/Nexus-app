5Release process

No release has been published: gh release list returns nothing and versionCode is 1 Implemented. The Gradle build enforces two release rules: NEXUS_API_URL must start with https:// (preReleaseBuild check), and release builds minify and shrink resources Implemented. Since v2.0 a release signing config reads keystore.properties (git-ignored) or NEXUS_KEYSTORE_* environment variables, and the upload key was created with scripts/create-upload-keystore.ps1 (AUD-08 fixed). CI does not have the key yet, so CI release artifacts remain unsigned until the secrets are added.

5.1Release checklist

Items marked Recommendation are recommendations for the first release. The others restate rules the repository already enforces or documents.

  1. CI (CI-01, CI-02) is green on the release commit; this requires IMP-01. Recommendation
  2. Backend tests pass locally: npm ci && npm test.
  3. Android unit tests pass: ./gradlew test. Instrumented tests pass on at least one API 24 and one current device. Recommendation
  4. Run the offline acceptance check in docs/ONLINE_OFFLINE.md (six steps) against the target API.
  5. Increment versionCode/versionName in app/build.gradle.kts (2 / 2.0.0 for the final PoE). Settings shows BuildConfig.VERSION_NAME.
  6. Hosted API is healthy over HTTPS with persistent storage and a stable JWT_SECRET (NX-11-DEP).
  7. Set repository variable NEXUS_API_URL to the HTTPS URL ending in /.
  8. Sign the APK/AAB with the release keystore held outside the repository (IMP-07). Recommendation
  9. Do not seed test accounts on a public host (AUD-14). Recommendation
  10. Add a dated entry to PROJECT_IMPROVEMENTS.md; tag the commit and create a GitHub release with the signed artifacts. Recommendation
