Purpose and product summary

Nexus is an Android app for personal project planning and habit tracking, backed by a small Node.js/Express REST API in backend/. The README describes it as "a calm, focused Android workspace for project planning and habit tracking". This document records what the product does at the evidence baseline, what it deliberately does not do, and how each requirement can be accepted. Requirement IDs (FR-nn, NFR-nn, CON-nn) are referenced by every other deliverable.

How to read status. {{F}} means the behaviour exists in source at the baseline commit; it does not by itself mean the behaviour was exercised end-to-end on a device for this package. Verified test results are listed in [[NX-09-TDH]]. Gaps are tracked as findings in [[NX-08-AUD]] and as tasks in [[NX-06-PLAN]].

There is no administrator, collaborator or shared-project role. The README's test-credential table labels one seeded account "Global system administrator", but the API has no role field or role checks, so that account is an ordinary user {{F}}. See [[AUD-09]].

Scope

In scope (implemented)

  • Account lifecycle: register, sign in, persisted session, sign out, profile, preferences, password change, account deletion.
  • Projects with tasks (due date, priority, status, labels, checklist), search and filters.
  • Habits with daily completion, streaks, points, levels, badges and CSV export.
  • Offline-first local saves with an ordered upload queue, sync status banner and conflict review.
  • English, isiZulu and Setswana for resource-backed strings; light/dark/system theme; animated splash that respects reduced motion.

Out of scope or planned (not implemented)

From PROJECT_IMPROVEMENTS.md ("Still planned") and docs/POE_PART_2_ADDENDUM.md: board/calendar/timeline views, recurring tasks and reminders, push notifications, attachments/templates/archive, collaboration/roles/comments, account recovery, Google SSO, general import/export, widgets, complete feature-screen localisation, tablet layouts, and SQLite on the server. None of these exist in code {{F}}. A "Task due-date reminders" switch exists in Settings but only stores a preference; see [[FR-05]] and [[AUD-10]].

Functional requirements

Acceptance criteria are written so a tester can run them against the debug build and a local API (setup in [[NX-11-DEP]]).

Non-functional requirements

Quality requirements evidenced in the implementation
IDRequirementEvidence / status
NFR-01Credentials and tokens are protected: bcrypt (cost 12) password hashes; JWT secret of at least 32 characters enforced at startup; token stored encrypted on the device; auth endpoints rate-limited to 10 requests per 15 min per IP.server.js, TokenManager.kt, server.test.js {{F}}
NFR-02Release builds use HTTPS only; cleartext HTTP is allowed only in debug builds.network_security_config.xml (main/debug), preReleaseBuild check {{F}}

NFR-05Accessibility: icon buttons carry content descriptions; reduced motion is respected; fallback brand colours were chosen for contrast.Code review only {{F}}; no formal accessibility audit has been run {{U}}
NFR-06Compatibility: Android 7.0 (API 24) and later; target/compile SDK 37.app/build.gradle.kts {{F}}
NFR-07Responsiveness on poor networks: 5 s connect timeout and 15 s call timeout, after which cached data is shown.RetrofitClient.kt {{F}}

Success measures

The repository defines no product metrics or analytics. PROJECT_IMPROVEMENTS.md asks that each feature define "one measurable success outcome", but none is recorded {{U}}. {{R}} Before the final PoE, agree on two or three measures that can be checked during testing, for example "a task created offline appears on the server within one sync cycle of reconnecting" (FR-16).
