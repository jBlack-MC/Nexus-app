Purpose and product summary

Version 2.0 update (Part 3). Requirements FR-21 to FR-23 (Google SSO, real-time push, due-date reminders) are new. FR-05 and FR-18 are now fully implemented, and the defects behind FR-01 and FR-02 are fixed. Each row states its current status.

Nexus is an Android app for personal project planning and habit tracking, backed by a small Node.js/Express REST API in backend/. The README describes it as "a calm, focused Android workspace for project planning and habit tracking". This document records what the product does at the evidence baseline, what it deliberately does not do, and how each requirement can be accepted. Requirement IDs (FR-nn, NFR-nn, CON-nn) are referenced by every other deliverable.

How to read status. {{F}} means the behaviour exists in source at the baseline commit; it does not by itself mean the behaviour was exercised end-to-end on a device for this package. Verified test results are listed in [[NX-09-TDH]]. Gaps are tracked as findings in [[NX-08-AUD]] and as tasks in [[NX-06-PLAN]].

There is no administrator, collaborator or shared-project role. The README's test-credential table labels one seeded account "Global system administrator", but the API has no role field or role checks, so that account is an ordinary user {{F}}. See [[AUD-09]].

Scope

In scope (implemented)

  • Account lifecycle: register, sign in (email/password or Google SSO), persisted session, sign out, profile, preferences, password change, account deletion.
  • Notifications: scheduled due-date reminders and real-time push of changes made on another device.
  • Projects with tasks (due date, priority, status, labels, checklist), search and filters.
  • Habits with daily completion, streaks, points, levels, badges and CSV export.
  • Offline-first local saves with an ordered upload queue, sync status banner and conflict review.
  • English, isiZulu and Setswana on every screen; light/dark/system theme; animated splash that respects reduced motion.

Out of scope or planned (not implemented)

From PROJECT_IMPROVEMENTS.md ("Still planned") and docs/POE_PART_2_ADDENDUM.md: board/calendar/timeline views, recurring tasks, attachments/templates/archive, collaboration/roles/comments, account recovery, general import/export, widgets, tablet layouts, and SQLite on the server. None of these exist in code {{F}}. Google SSO, push notifications, reminders and full localisation were planned for the final PoE and are now implemented (FR-21 to FR-23, FR-18).

FR-21Sign in with Google (single sign-on)."Continue with Google" appears on Login and Register when the build has a Web client ID. Credential Manager returns a Google ID token; POST /api/auth/google verifies signature, audience, expiry and email verification with Google, creates the account on first use (201) or links an existing email (200), and returns a Nexus JWT. Invalid tokens give 401; an unconfigured server gives 503, which the app explains. A Google-only account cannot use password sign-in (401) or change password (409).GoogleSignIn.kt, server.js, part3.test.js (3 tests, stubbed verifier), AuthErrorMessagesTest {{F}}. End to end with real Google: {{U}} until the OAuth clients are created
FR-22Real-time push notifications.After sign-in the app registers its FCM token (POST /users/me/devices, at most 10 per user; a token belongs to one account). When a synced change is applied, the API pushes "Project "X" added on another device" to the user's other devices, excluding the sender. The receiving app shows the notification and refreshes its offline cache. Dead tokens are pruned. "Send test notification" in Settings triggers a server push and shows a local one.Push.kt, push.js, part3.test.js (5 tests) {{F}}; local display verified on device; FCM delivery {{U}} until a Firebase project is configured
FR-23Due-date reminders.With reminders on, a WorkManager job runs about every 12 hours (and immediately after sign-in or switching reminders on). It reads the offline cache and posts "Tasks need your attention: n overdue and m due today" with up to three task titles. It runs while the app is closed and without network. Android 13+ asks for the notification permission.Reminders.kt, ReminderPlanner + ReminderPlannerTest {{F}}; verified on device ("1 overdue and 2 due today")

Non-functional requirements

Quality requirements evidenced in the implementation
IDRequirementEvidence / status
NFR-01Credentials and tokens are protected: bcrypt (cost 12) password hashes; JWT secret of at least 32 characters enforced at startup; token stored encrypted on the device; auth endpoints (including Google sign-in) rate-limited to 10 requests per 15 min per client IP (proxy-aware with TRUST_PROXY); Google ID tokens verified server-side.server.js, TokenManager.kt, server.test.js {{F}}
NFR-02Release builds use HTTPS only; cleartext HTTP is allowed only in debug builds.network_security_config.xml (main/debug), preReleaseBuild check {{F}}
NFR-03Data isolation: each account sees only its own server data and cached rows.Per-user maps on the server; userId-scoped DAO queries; sync ownership test {{F}}
NFR-04Durability: a local save is never lost because an upload failed; server writes are atomic (temp file + rename) and serialised by a mutex.SyncManager.save(), saveDatabase() {{F}}; corrupt-file risk [[AUD-01]]
NFR-05Accessibility: icon buttons carry content descriptions; reduced motion is respected; fallback brand colours were chosen for contrast.Code review only {{F}}; no formal accessibility audit has been run {{U}}
NFR-06Compatibility: Android 7.0 (API 24) and later; target/compile SDK 37.app/build.gradle.kts {{F}}
NFR-07Responsiveness on poor networks: 5 s connect timeout and 15 s call timeout, after which cached data is shown.RetrofitClient.kt {{F}}
NFR-08Observability: structured JSON logs (Pino) with request ids and redaction of passwords and authorization headers; /health liveness endpoint.server.js {{F}}
